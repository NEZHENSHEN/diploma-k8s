# Разработка программной системы анализа сетевой связности и формирования сетевых политик в Kubernetes

## 1. Proof of concept
Тестовый стенд: 3 сервиса (простейшие приложения на fast API)
- [x] Модель вершины и ребра. Выбранная и описанная [Модель графа](<../Решение/Модель графа.md>) сработала на тестовом стенде. ✅ 2026-11-08
- [x] Стенд: кластер с [Cilium](<../Теория/Cilium.md>) исполняющим [Network Policy](<../Теория/Network Policy.md>). Сетевые политики работают и блокируют трафик между подами. ✅ 2026-11-08
- [x] Граф требуемой связности. Описан граф в формате YAML и реализован в программе в виде структуры данных [NetworkX](<../Теория/NetworkX.md>). ✅ 2026-11-08
- [x] Граф разрешенной связности. Написать программу, которая берёт данные из [Kubernetes API](<../Теория/Kubernetes API.md>) и строит граф разрешенной связности [NetworkX](<../Теория/NetworkX.md>). ✅ 2026-11-08
- [x] Граф наблюдаемой связности. Из [OpenTelemetry](<../Теория/OpenTelemetry.md>) получен граф в формате [Модель графа](<../Решение/Модель графа.md>). ✅ 2026-11-09
- [x] Сравнение графов. Графы сравнены и посчитана их разность в программе. ✅ 2026-11-09
- [x] Эксперименты по выбору вершины. Сравнить pod, service, namespace. ✅ 2026-11-09
## 2. MVP
Тестовый стенд: 4-6 микросервисов генерирующих трафик
- [x] Единая модель данных и общий формат графов. Все три графа строятся в одном формате прописанном в [Модель графа](<../Решение/Модель графа.md>). ✅ 2026-11-09
- [x] Граф разрешенной связности на наборе тестовых политик совпадает с ручным расчётом. ✅ 2026-11-09
- [ ] Граф наблюдаемой связности собирается за прогон нагрузки.
- [x] Анализ разности графов. Приложение сравнивает графы и классифицирует расхождения (8 различных случаев). ✅ 2026-11-09
- [ ] Программа выдаёт текстовый отчет (ребро, класс, причина, рекомендация).
## 3. Нормальный объем
Тестовый стенд: 100 микросервисов
- [ ] Приложение анализирует разницу между графами и формирует рекомендации по [Network Policy](<../Теория/Network Policy.md>), которые можно посмотреть, проверить и при необходимости применить в Kubernetes.
