# Разработка программной системы анализа сетевой связности и формирования сетевых политик в Kubernetes

## 1. Proof of concept
Тестовый стенд: 3 сервиса (простейшие приложения на fast API)
- [ ] Модель вершины и ребра. Выбранная и описанная [[Модель графа]] сработала на тестовом стенде.
- [ ] Стенд: кластер с [[Cilium]] исполняющим [[Network Policy]]. Сетевые политики работают и блокируют трафик между подами.
- [ ] Граф требуемой связности. Описан граф в формате YAML и реализован в программе в виде структуры данных [[NetworkX]]. 
- [ ] Граф разрешенной связности. Написать программу, которая берёт данные из [[Kubernetes API]] и строит граф разрешенной связности [[NetworkX]].
- [ ] Граф наблюдаемой связности. Из [[OpenTelemetry]] получен граф в формате [[Модель графа]].
- [ ] Сравнение графов. Графы сравнены и посчитана их разность в программе.
- [ ] Эксперименты по выбору вершины. Сравнить pod, service, namespace.
## 2. MVP
Тестовый стенд: 4-6 микросервисов генерирующих трафик
- [ ] Единая модель данных и общий формат графов. Все три графа строятся в одном формате прописанном в [[Модель графа]].
- [ ] Граф разрешенной связности на наборе тестовых политик совпадает с ручным расчётом. 
- [ ] Граф наблюдаемой связности собирается за прогон нагрузки.
- [ ] Анализ разности графов. Приложение сравнивает графы и классифицирует расхождения (8 различных случаев).
- [ ] Программа выдаёт текстовый отчет (ребро, класс, причина, рекомендация).
## 3. Нормальный объем
Тестовый стенд: 100 микросервисов 
- [ ] Приложение предлагает [[Network Policy]], которая будет исправлять возникающую ошибку.
## 4. Фичи на развитие
- [ ] Усложнение среды. Программа может работать когда на стенде развернуты [[Service Mesh]], [[Prometheus]], [[Kiali]] как часть стенда.
- [ ] Оптимизация. Насколько большой стенд сможет выдержать программа.
